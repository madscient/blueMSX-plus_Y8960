# doc/fork/ai — AI 向けの作業規則

**この階層は AI が読む前提の文書だけを置く。**
上流（Hesoten/blueMSX-plus）は `.gitignore` で `CLAUDE.md` を除外しており、
この種の文書をリポジトリに置かない方針だが、**このフォークでは場所を限定して置く**
（2026-09-12 ユーザー判断）。限定とは次の 2 か所のこと。

| 場所 | 役割 |
|---|---|
| ルートの `CLAUDE.md` | **索引のみ。** 規則の中身は書かない |
| `doc/fork/ai/`（本階層） | 規則の本体 |

人間向けの事実と索引は `doc/fork/README.md`、Y8960 の実装計画は
`doc/fork/y8960/implementation-plan.md`。

## 上流に出すものへ混ぜない

**プルリクエストや issue に、この階層の文書を混ぜないこと。**
上流はこの種の文書を置かない方針なので、送りつける形になる。

上流へ出す枝は `upstream/develop` から切り直し、**コードだけを載せる**
（`doc/fork/README.md` の「上流へ出すとき」）。
`doc/` 配下が差分に入っていないことを、出す前に確かめる。

```sh
# 上流へ出す枝に doc/ が混ざっていないか
git diff --name-only upstream/develop..<枝> | grep '^doc/' && echo "MIXED IN"
```

## 作業の記録と確度

主題ごとに作業計画と実行経緯の文書を持ち、決定・却下・訂正はその都度書く。
Y8960 なら `y8960/implementation-plan.md`。口頭で終えない。

主張には確度を併記する。走らせて確かめたなら**確認済み**とその手段を、
読んだだけなら**確認済み(読解)** とファイル名と行を、作っただけなら**未検証**、
出典を示せないなら**推測**と根拠を一行。

**外に出る値を決める直前に一声かける。** `RomType` の数値、ミキサー種別の
識別子、I/O アドレス、設定ファイルのキー、セーブステートの節名。
これらは後から変えると利用者のファイルに波及する。確定したものは
`y8960/implementation-plan.md` §6 にだけ書く（二重に持つと片方が古くなる）。

### コミットの分け方

**フェーズ単位ではなく、論理単位で分ける。** フェーズは作業の区切りであって、
変更の論理単位ではない。Phase 0 が 1 コミットで済んだのは「器を作る」という
単一の論点だったからで、途中で切ると中途半端な状態が残るためである。

**上流に出せる変更は、必ず単独のコミットにする。**
2026-09-12 に IoPort の多重化を Y8960 の文書と同じコミットに入れてしまい、
上流へ出すときに**別ブランチで書き直す**ことになった。
最初から分かれていれば cherry-pick で済んだ。

| 変更の種類 | 置き場所 |
|---|---|
| 上流のバグ修正・上流に還元できるもの | **単独のコミット。** `upstream/develop` から切り直せる形に |
| Y8960 固有の実装 | 機能ごとに 1 コミット。各コミットでビルドが通ること |
| 設計を説明する文書 | **対応するコードと同じコミット**（なぜそう作ったかが一緒に残る） |
| 実測結果・経緯の追記 | **別コミット**（後から分かったことなので） |

### 上流のファイルに触ったら記録する

**衝突面はできるだけ小さく保つ。** 上流のファイルを触ったまま放置すると、
上流がそこに手を入れた瞬間に解決の手間になる。触ったファイルと理由は
`y8960/implementation-plan.md` に書く。

**`Src/Memory/IoPort.{c,h}` は 2026-09-12 に実際に変更した**（1 ポートに
複数デバイスを登録できるようにし、`ioPortUnregister` に `ref` を足した）。
`ioPortUnregister` の呼び出し 200 箇所を持つ **53 ファイル**にも手が入っている。
経緯は `y8960/implementation-plan.md` §4.2。

**Phase 0 でさらに 10 本触った**（2026-09-12）。`MediaDb.{h,cpp}`、

## 出す前に

`origin` は GitHub にある。**push したオブジェクトは親リポジトリから SHA で
辿れて、後から消せない。** 点検は push の前にしか意味が無い。

- **ローカル固有のパスが混入していないか。** 成果物にもコミットメッセージにも
  書かない。スクリプトでパスが要るときは環境に依存しない形にする
- **個人情報が混入していないか。** 成果物にもコミットメッセージにも書かない
- 未コミットの変更が残っていないか
- 文書の索引と実体が食い違っていないか
