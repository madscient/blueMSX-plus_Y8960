# Y8960 対応 — 使い方

このフォークの blueMSX+ は、音源カートリッジ **Y8960** をエミュレートします。

Y8960 のハードウェアは開発中です。エミュレーションは現時点の仕様に沿っており、
**仕様が変われば動作も変わります。** ハードウェアの仕様は
[hra1129/Y8960_Cartridge](https://github.com/hra1129/Y8960_Cartridge) で
開発されています。

## Y8960 の構成

Y8960 は 6 つのブロックでできています。blueMSX+ では一式をカートリッジとして
まとめて挿すほかに、**ブロックごとに独立したデバイス**としてマシン構成に
1 つずつ追加することもできます。

| 表示名 | 内容 |
|---|---|
| Y8960 SCC | SCC、バンクメモリ、I/O イネーブラ、メモリマップド I/O。**カートリッジ ROM はここに載せます** |
| Y8960 OPLLEX | YM2413 相当。チャンネルごとに 4 種類の音色 ROM を切り替えられ、チャンネルごとに定位を置けます |
| Y8960 OPL2EX | YM3812 + ADPCM-B 相当 |
| Y8960 SSGS | YM2149 相当 ×2。チャンネルごとの音量と定位付き |
| Y8960 MSX-TIMER | 4 本のカウンタと割り込み |
| Y8960 MSX-MIXER | ブロックごとの音量（**ハードウェア側が未実装のため、現状は音に影響しません**） |

## カートリッジとして挿す

**一式をまとめて挿すのがいちばん簡単です。** 6 つのブロックが一度に入ります。

- **ROM イメージ無しで挿す** — **ファイル → ROMスロット → 特殊カートリッジ →
  Y8960 Cartridge**
- **ROM イメージを載せて挿す** — **ファイル → ROMスロット** から ROM イメージを
  挿入し、**ROM タイプ** に **Y8960 Cartridge** を選びます。ROM はバンクメモリに
  載ります（ファームウェアを使う場合はこちら）

コマンドラインから挿す例:

```
blueMSX+.exe /machine "<マシン構成名>" /rom1 <ROM ファイル> /romtype1 Y8960
```

カートリッジを抜くと 6 ブロックとも外れます。

**マシン構成にも Y8960 のブロックが入っているマシンで使わないでください。**
同じブロックが二重になり、音量が倍になります。

## マシン構成に追加する

ブロックを選んで載せたいときは、こちらを使います。

**ツール → マシン構成編集** を開き、**メモリ** タブの **追加...** で
上の表のタイプを選びます。**カートリッジの形では** 6 つすべてを追加すると
Y8960 一式になります（本体内蔵の形は後述）。

**Y8960 SCC だけは ROM イメージを指定します**（カートリッジ ROM）。
ほかの 5 つは ROM を持ちません。

Y8960 SCC だけをカートリッジとして挿すこともできます。ほかの 5 つを
マシン構成に追加しておき、**ファイル → ROMスロット** から ROM イメージを
挿入して、**ROM タイプ** に **Y8960 SCC** を選びます。
**Y8960 SCC はどちらか一方の方法で 1 つだけ**にしてください。

設定ファイル（`config.ini`）を直接編集する場合、`[Slots]` に書く番号は次のとおりです。

| タイプ | 番号 | コマンドラインでの名前 |
|---|---|---|
| Y8960 OPLLEX | 200 | `Y8960OPLLEX` |
| Y8960 OPL2EX | 201 | `Y8960OPL2EX` |
| Y8960 SSGS | 202 | `Y8960SSGS` |
| Y8960 MSX-TIMER | 203 | `Y8960TIMER` |
| Y8960 MSX-MIXER | 204 | `Y8960MIXER` |
| Y8960 SCC | 205 | `Y8960SCC` |

206 は以前の Y8960 DCSG の番号です。DCSG はハードウェアから無くなったので、`config.ini` に
206 の行が残っていても何も追加されません。消して構いません。

一式をまとめて挿すときの **Y8960 Cartridge** は番号 207、コマンドラインでの名前は
`Y8960` です。**こちらはカートリッジ専用で、マシン構成には追加できません。**

v3.1.1-y8960.2 までの版で作った `config.ini` は番号が 180-187 なので、上の表のとおり 20 を足して
書き換え、DCSG（186）の行は消してください。カートリッジの履歴とセーブステートも同じ番号を持つため、
そのまま使えません。

コマンドラインから Y8960 SCC だけをカートリッジとして挿す例:

```
blueMSX+.exe /machine "<マシン構成名>" /rom1 <ROM ファイル> /romtype1 Y8960SCC
```

## カートリッジとして使う場合と、本体内蔵の場合

Y8960 はカートリッジとして挿す形と、本体に内蔵される形の 2 通りがあります。
**動作が違います。**

| | カートリッジ | 本体内蔵 |
|---|---|---|
| I/O イネーブラ | **有り。** リセット直後はすべて閉じています | **無し。** すべてのブロックが常に応答します |
| メモリマップド I/O | 有り | 無し |
| SSGS | 本体の PSG に重ねて発音します。**読み出しはできません** | **本体の PSG の代わりになります。** 読み書きでき、ジョイスティック・カセット・かな LED が繋がります |

**本体内蔵の形**にするには、マシン構成編集の **基盤タイプ** で **MSX2++** を選びます。
すると次のようになります。

- SSGS が本体の PSG になります。**Y8960 SSGS はブロックとして追加しないでください**
- I/O イネーブラとメモリマップド I/O が無くなり、すべてのブロックが常に応答します
- **バンクメモリと SCC は残ります。** 使う場合は Y8960 SCC を追加します

ほかのブロックは必要なものを追加します。

なお、カートリッジの形で Y8960 SCC を追加しなかった場合も、イネーブラを開く手段が
無くなるため、ほかのブロックは常に応答します。

MSX2++ の VDP は V9968 になる予定ですが、現在のこのフォークでは対応していません。

## I/O とメモリマップド I/O

**カートリッジの場合**、ブロックの I/O ポートは I/O イネーブラを開くまで応答しません。
イネーブラはメモリマップド I/O にあり、見える条件は「バンクメモリと SCC」の表のとおりです。
メモリマップド I/O の**トンネル**からは、イネーブラを開かなくても各ブロックに書き込めます。

| ブロック | I/O ポート | イネーブラ | トンネル |
|---|---|---|---|
| OPLLEX | `7Ch` アドレス / `7Dh` データ（書き込みのみ） | `7FF6h` bit 0 | `7FF4h` / `7FF5h` |
| OPL2EX | `C0h` アドレス・ステータス / `C1h` データ | `7FFFh` bit 0 | `7FEEh` / `7FEFh` |
| SSGS | `A0h` レジスタ / `A1h` データ（書き込みのみ） | `7FFFh` bit 4 | `7FEAh` / `7FEBh` |
| MSX-TIMER | `B0h`-`B3h` | `7FFFh` bit 7 | なし |
| MSX-MIXER | `B6h` レジスタ / `B7h` データ（書き込みのみ） | なし | なし |

**トンネルは書き込みのみです。** 閉じているイネーブラの I/O ポートを読むと `FFh` が返ります。

MSX-MIXER のアドレスは暫定です。

### バンクメモリと SCC

| | |
|---|---|
| バンク | 256KB。`#0`-`#15` が ROM、`#16`-`#31` が RAM |
| RAM への書き込み | RAM モード（`48FBh`）で `#16`-`#31` を出したとき、`6000h`-`BFFFh` に書き込めます。**`4000h`-`5FFFh` には書き込めません** |
| ミラー | `4000h`-`7FFFh` の内容は `C000h`-`FFFFh` にも、`8000h`-`BFFFh` の内容は `0000h`-`3FFFh` にも読み出せます。ミラーには書き込めません |
| SCC | BANK2 のバンクレジスタに `3Fh` を書くと `9800h` に SCC が出ます。RAM モードでは、BANK1 に `3Fh` を書くと `7800h` にも出ます。BANK0 と BANK3 には出ません |
| メモリマップド I/O | `7FE0h`-`7FFFh`。RAM モードで BANK1 に SCC または `#16`-`#31` が出ているときは見えません |

## ブロックごとの動作

### OPLLEX

YM2413 と同じレジスタに加えて、**`40h`-`48h`**（チャンネル 0-8）の
bit 1-0 で、そのチャンネルが使う音色 ROM を選びます。

| 値 | 音色 |
|---|---|
| 0 | OPLL（YM2413） |
| 1 | OPLL-X（YM2423） |
| 2 | OPLL-P（YMF281） |
| 3 | VRC7 |

ユーザー音色（音色 0）はチャンネルで共通です。バンクを切り替えても変わりません。

**`50h`-`58h`**（チャンネル 0-8）はステレオの定位です。1 が左端、128 が中央、255 が右端で、
0 は中央と同じです。リセット直後は中央です。リズム音は元のチャンネルの定位に従います
（BD は `56h`、HH と SD は `57h`、TOM と CYM は `58h`）。

プリセット音色は各チップの ROM そのものではなく、互換の音色データです（末尾の「帰属表示」）。
そのため OPLL の音色は、本体の MSX-MUSIC と完全には一致しません。

### OPL2EX

YM3812 のレジスタ配置で、**`E0h`-`F5h` による 4 種類の波形選択**に対応しています
（`01h` の bit 5 で有効になります）。リズム音には波形選択が効きません。

ADPCM-B のサンプル RAM は **256KB** です。
Y8960 の ADPCM にはサンプル ROM が無いので、レジスタ `08h` の bit 0
（Y8950 では ROM への切り替え）は何も切り替えません。

MSX-AUDIO のキーボード端子、13bit DAC、I/O ポート、および `07h` の bit 3（SP-OFF）は持ちません。

### SSGS

| アドレス | 内容 |
|---|---|
| `00h`-`0Fh` | 1 系統目（YM2149 と同じ配置） |
| `10h`-`1Fh` | 2 系統目（同上）。`1Fh` の下位 4bit は LED です（エミュレータでは表示されません） |
| `20h`-`22h` / `24h`-`26h` | 1 系統目 / 2 系統目のチャンネル A/B/C の**音量**。0-127 のリニアで、127 が最大。bit 7 は無視されます |
| `28h`-`2Ah` / `2Ch`-`2Eh` | 1 系統目 / 2 系統目のチャンネル A/B/C の**定位**。1 が左端、128 が中央、255 が右端、0 は中央 |
| `23h` `27h` `2Bh` `2Fh` | 未接続 |

**リセット直後は音量 127、定位は中央です。** 定位は両端と中央の値が決まっており、
間はパワーパンニング（中央で左右とも約 0.7 倍）です。

本体内蔵の場合、音量と定位は書いた値がそのまま読み出せます。
2 系統目の GPIO（`1Eh` / `1Fh`）には何も繋がっておらず、書いた値を憶えるだけです。

### MSX-MIXER

`B6h` / `B7h` に書いた値は保持されますが、**現状は音に影響しません。**
ハードウェア側のレジスタ仕様が決まっていないためです。

## 音量の調整

**Y8960 の音量・パン・有効/無効は、ミキサー画面に出ません。**
すべてのブロックの音がまとめて 1 つのチャンネルに入っています。
変更するには、エミュレータを終了してから設定ファイル `bluemsx.ini` を編集します。

```
sound.mixerChannel.MIXER_CHANNEL_Y8960.enable=yes
sound.mixerChannel.MIXER_CHANNEL_Y8960.pan=50
sound.mixerChannel.MIXER_CHANNEL_Y8960.volume=90
```

基盤タイプが MSX2++ の場合、本体の PSG の音もこのチャンネルに入ります。

## ファームウェア

Y8960 を駆動する拡張 BASIC と BIOS が
[madscient/MsxSoundSuiteExtension](https://github.com/madscient/MsxSoundSuiteExtension)
で開発されています。**本エミュレータには同梱していません。**
入手方法と利用条件はそちらを参照してください。

## 動作の確認が済んでいない機能

次の機能は実装されていますが、動作の確認が済んでいません。

- 基盤タイプが MSX2++ のマシンで OPLLEX / OPL2EX が応答すること
  （MSX-TIMER と SSGS は確認済み）
- Y8960 SCC を追加しないカートリッジ形のマシンで、ほかのブロックが常に応答すること
- **Y8960 Cartridge** に ROM イメージを載せてファームウェアを動かすこと
- ステートセーブとロード
- ファームウェア（MsxSoundSuiteExtension）での動作
