# Makoto（YM2608 OPNA カートリッジ）対応 — 計画と経緯

対象読者は開発者と AI。Y8960 とは独立した、音源カートリッジの追加。

上流候補なので、**`upstream/develop` から切った枝 `feature/makoto-opna` に、
コードだけのコミットで作る**（`doc/fork/README.md` の「上流へ出すとき」）。
この文書は上流に出さない。

## 1. 調べて分かったこと

### 1.1 Makoto のハードウェア

出典は VGMPlay MSX の Makoto ドライバ（sharksym/vgmplay-sharksym の
`src/drivers/Makoto.asm`）。**確認済み(読解)**。製品ページ（Supersoniqs）と
MSX Resource Center の開発スレッドには I/O の記述が無い。

| | |
|---|---|
| チップ | YM2608 (OPNA) + YM3016 (DAC) |
| クロック | 8 MHz |
| I/O ポート | `14h` 表アドレス / 表ステータス、`15h` 表データ、`16h` 裏アドレス / 裏ステータス、`17h` 裏データ |
| 表（`14h`/`15h`） | FM 1–3ch、SSG、リズム（ADPCM-A）、共通レジスタ |
| 裏（`16h`/`17h`） | FM 4–6ch、ADPCM-B |
| ADPCM-B のメモリ | ドライバは **1bit DRAM モード**（裏 `01h` の bit1 = 0）に設定する。アドレスは 4 バイト単位 16bit なので上限 256 KB |
| `14h` の読み | ドライバは読まない。コメントに「Music Module とバスが衝突する」とある |
| 検出 | 裏 `00h` に `80h`（START）を書き、裏ステータスの bit5 が立つことを見る |

**利用者から得たこと**（2026-09-22）: ADPCM-B の RAM は **256 KB**、
**/IRQ は MSX の /INT に繋がっている。** どちらもドライバからは決まらなかった
（ドライバは容量を調べず、割り込みを切って使う）。

**未確認**: `14h` の読みで何が返るか（本物のステータスか、衝突で不定か）。

### 1.2 ymfm

GitHub の aaronsgiles/ymfm、`81aec25ccb`（2026-07-27）時点。**確認済み(読解)**。

| | |
|---|---|
| ライセンス | BSD-3-Clause（GPLv2 と両立する） |
| OPNA の実装 | `ymfm_opn.{h,cpp}` の `ym2608` |
| 依存 | `ymfm.h`、`ymfm_fm.{h,ipp}`、`ymfm_adpcm.{h,cpp}`、`ymfm_ssg.{h,cpp}` |
| 同居しているもの | `ymfm_opn.cpp` には OPN / OPNB / OPN2 系の他チップも入っている |

**ymfm がホストに任せているもの**（`ymfm_interface` の仮想関数）:

| | ymfm の口 | blueMSX 側で要るもの |
|---|---|---|
| リズムの波形 ROM（8 KB） | `ymfm_external_read(ACCESS_ADPCM_A, …)` | 利用者が置くファイルを読む（§2） |
| ADPCM-B の RAM | `ymfm_external_read/write(ACCESS_ADPCM_B, …)` | カートリッジが持つバッファ |
| タイマ A / B | `ymfm_set_timer` | ボードのタイマに繋ぐ。**割り込みを使わないソフトもステータスのフラグで待つ**ので要る |
| IRQ | `ymfm_update_irq` | 繋ぐかどうかは §1.1 の未確認事項による |
| 出力 | `generate()` は FM と SSG を共通のレートに揃えて返す。FM は 8 MHz / 144 ≈ 55.6 kHz、SSG は 8 MHz / 32 = 250 kHz で作られ、別々に回す口は `ym2608` の protected メンバー | それぞれをミキサーのレートへ変換する（§4.5） |

`ym2608::reset()` はリズム 6 音の開始・終了アドレス（`0000h`–`1FFFh`）を
自分で設定する。ROM の中身だけを渡せばよい。

### 1.3 リズム ROM

MAME は YM2608 の内蔵 ROM を `ym2608_adpcm_rom.bin`（8 KB、CRC32 `23c9e0d8`）として扱う
（`src/devices/sound/ymopn.cpp`、**確認済み(読解)**）。中身は YM2608 のマスク ROM の
吸い出しで、**再配布できない**。

### 4.1 作りの要点

| | どうしたか | なぜ |
|---|---|---|
| 生成 | `ym2608::generate()` は使わない。`ym2608` を継承した `Ym2608Chip` から FM+リズム+ADPCM（ステレオ）と SSG を別々に回す。レートは clock ÷ (24 × プリスケーラ) と clock ÷ 32 / 16 / 8 で、8 MHz・プリスケーラ 6 なら 55,556 Hz と 250,000 Hz | `generate()` は 2 つを共通のレートに揃えるために同じ値を繰り返す。経緯と測定は §4.5 |
| レート変換 | ストリームごとに窓付き sinc。ミキサーのサンプルがチップのサンプルの間のどこに落ちるかは、`clock` 対 `sampleRate × 1 サンプルのクロック数` の整数で数える | 誤差を貯めない。高域のレベルと、変換で混ざる成分の測定は §4.5（人が聴いての評価はしていない） |
| 混合 | L = FM_L + SSG、R = FM_R + SSG。SSG は 3 声の和 × 2/3 | ymfm の `examples/vgmrender` と同じ。2/3 は `generate()` が 1 本に混ぜるときの係数で、**実機の値ではない**（実機の FM と SSG の比は基板のミキサー回路で決まる。§4.5） |
| 出力の倍率 | 2 倍 | ミキサーは音量 1024 を掛けて 4096 で割る。フルスケールの OPNA がミキサーの約半分になる（**推測**: 他の音源との音量の釣り合いは聴いていない） |
| タイマ | ymfm が求めるクロック数をボード時間に換算して `boardTimerAdd`。**満了から再設定されるときは、予定時刻から数える** | ボードは命令の切れ目でタイマを発火するので、コールバックは遅れる。発火時刻から数えると周期が伸びる |
| ビジー | ymfm が求めた終了時刻をボード時間で持つ | |
| レジスタ書き込み・読み出し | 前に `mixerSync` | 音の生成を書き込み時刻まで進めてから状態を変える |
| peek | 表ステータスだけ返し、他は `FFh` | 裏ステータスの読みはフラグを書き戻し、裏データの読みは ADPCM-B のアドレスを進める（`ymfm_opn.cpp` の `read_status_hi` / `read_data_hi`） |
| ROM が無いときのリズム | ymfm に `08h` を返す | ニブル 0 と 8 が最小の段を足して引くので、アキュムレータは 0 と 2 を行き来するだけになる（`ymfm_adpcm.cpp` の `clock` の復号）。`00h` を返すとずれて行く（§4.2 の b05） |
| デバッガのレジスタ表示 | 書き込みを自前で控える | ymfm はレジスタを外に出していない |
| セーブステート | ymfm の `save_restore` のバイト列、タイマ、ビジー、2 本のストリームのクロックの端数と変換器が持つサンプル、ADPCM-B の RAM、レジスタの控え | ストリームの分は、保存したときとミキサーのレート・大きさが同じときだけ戻す。違えば頭から始める（§4.5） |

### 4.2 確かめたこと

**ビルド**（**確認済み**）: msvc2022 の Release / x64 で 0 エラー。追加したファイルからの
警告は 0 件（6 件の警告はすべて触っていない既存ファイル）。`blueMSX+.exe` は別の実行中の
プロセスが掴んでいたので、リンク先だけを `-p:OutDir=` で作業ツリーの外に変えた。

**登録**（**確認済み**）: そのビルドの `/listspecials` に `MAKOTO  Makoto` が出た（56 行中）。
**`/listromtypes` には出ない** — ROM イメージに掛けるマッパーの一覧で、Joyrex PSG も出ない。
Makoto の登録を確かめる手段にはならない。

**ホスト上の probe**（`tests/opna-probe.cpp`、**確認済み**）: `YM2608.cpp` と ymfm を
エミュレータから切り離してスタブと組み、38 項目がすべて OK（2026-10-04、`588325e5`。
`2ade339f` の時点では下の表の「セーブしてロード」までの 21 項目）。スタブは時間を進められ、
ボードタイマを命令の切れ目の遅れ（30 µs）込みで発火する。

**ビルドの出力は作業ツリーの外に向ける。** `build-probe.ps1` の `-Out` と `-ObjDir` に
外のパスを渡す。既定のままだと exe と中間ファイルが `tests/` に出て、どちらも gitignore
されていない（**確認済み**: `git check-ignore` が何も返さない）。

| 項目 | 期待値の出所 |
|---|---|
| FM の音程（F-Num 618、BLOCK 4 → 261.94 Hz） | OPN の F-Number の式（**推測**: 記憶による。ymfm からは取っていない） |
| SSG の音程（TP 284 → 440.14 Hz） | clock / (64 × TP)（同上） |
| リズム: ROM 無しで無音、ROM ありで鳴る | ROM ありで RMS 10619.5、無しで 11.4（`588325e5`。`2ade339f` では 10613.6 と 10.4） |
| リズムがひとりでに鳴り終わる（BD 1 打、`opnatest.asm` と同じ BD/SD の並び） | 1〜1.5 秒後の RMS が 0.0 |
| タイマ A の満了（1 回目・2 回目、前後 50 µs） | ymfm の 1 ステップ 144 クロック。**グルーの時間換算だけを確かめる**（ymfm の式そのものは確かめていない） |
| IRQ: マスク 0 で `boardSetInt` が呼ばれない / `1000h` で立ち、フラグのリセットで落ちる | |
| IRQ を繋いだ状態で、リセット後に放置しても割り込みが立たない | ymfm はリセットで IRQ の許可を `1Fh`（全部）にする（`ym2608::reset`）。立てば MSX は起動中に止まる |
| ビジー: 書き込み直後に立ち、100 µs 後に落ちる | |
| ADPCM-B の書き込みが RAM に届く（1bit DRAM で開始アドレス 1 → バイト 4、8bit DRAM で → バイト 32） | VGMPlay MSX の Makoto ドライバが 1bit DRAM で 4 バイト単位を前提にしている（§1.1）。**RAM の側を直接見ている**ので、往復ではない |
| セーブしてロードすると同じ音が出る / ロードしなければ違う | サンプル単位で比べる |
| 実レートで回した出力が `generate()` と一致する（プリスケーラ 6 / 3 / 2）/ 書き込みを 3 つ抜くと食い違う | `tests/opna-native-check.cpp`。ymfm だけを直接回す。§4.5 の前提 |
| 13.9 kHz の FM 音のレベルが 868 Hz と ±0.5 dB で揃う | OPN のオペレータの振幅は音程によらない（**推測**: OPN に音程で音量を変える機能が無いという記憶による。`588325e5` で 868 Hz から 17.4 kHz まで 0.00 dB に揃ったことと合う） |
| 変換で混ざる成分が、13.9 kHz の FM 音と 2,976 Hz の SSG 音に対して 50 dB 以上小さい | 測り方は §4.5 の「残り」 |
| 放置すると出力がちょうど 0 / 一定のレベルが一定に出る / 5 ms のレベルが、レベル × 長さの面積で出る | SSG のトーンとノイズを両方切ると、音量がそのまま出る |
| プリスケーラ 3 / 2 での FM と SSG の音程 | ymfm の表（FM は 2 倍 / 3 倍、SSG は 2 倍 / 4 倍） |
| プリスケーラ 2 で保存したステートを、作り直したチップに読んで音程が合う | エミュレータを起動し直してステートを読む場合に当たる |

**判別力**（**確認済み**、`2ade339f` の時点）: `YM2608.cpp` を 12 通りに壊した版（作業ツリーの外）で、

| 壊し方 | 落ちた項目 |
|---|---|

| b04 ROM を渡しても使わない | リズムが鳴る |
| b05 ROM 無しで `00h` を返す | リズムが無音 |
| b06 マスク 0 でも `boardSetInt` を呼ぶ | IRQ を繋がない |
| b07 ADPCM-B の書き込みを捨てる | ADPCM-B の 3 項目 |
| b08 ビジーを常に偽に | 書き込み直後のビジー |
| b09 ロードで ymfm の状態を戻さない | セーブとロード |
| b10 ロードでレート変換の端数を戻さない | セーブとロード |
| b11 IRQ を常に立った扱いにする | フラグのリセットで落ちる |
| b12 リセットでタイマ A を動かす | リセット後に放置、タイマ A の後（1 回目・2 回目）、`1000h` で立つ |

b02 は、スタブのタイマを遅れ無しで発火させていた間は**捕まらなかった**。遅れを
入れて初めて捕まった。

b11 は「リセット後に放置」の項目では**捕まらない。** ymfm は IRQ の状態が
変わったときにしか通知しないので、放置している間は立ちっぱなしの壊れが表に出ない。
この項目の判別力は b12 で示した。

**b03 と b10 が壊した箇所は `588325e5` で無くなった**（出力レートの分母、レート変換の端数）。
代わりは下の n11〜n14 と n05・n06。**残りの 10 通りは `588325e5` に掛け直していない。**
壊す対象のコード（タイマ、ROM、IRQ、ビジー、ADPCM-B、ymfm の状態の復元）と、それを見る項目は
どちらも変えていない。

**判別力**（**確認済み** 2026-10-04、`588325e5`）: 足した項目について、`YM2608.cpp` を 15 通りに
壊した版（作業ツリーの外）を作り、それぞれ落ちる項目があることを見た。

| 壊し方 | 落ちた項目 |
|---|---|
| n01 係数の行ごとの和を 1 に揃えない | 一定のレベルが一定に出る（振れ 18） |
| n02 0 が 1 個来ただけで積和を省く | SSG の混ざる成分、5 ms の面積、SSG の音程（プリスケーラ 2） |
| n03 プリスケーラが変わってもレートを変えない | プリスケーラ 3 / 2 の音程 4 項目 |
| n04 ロードでレートを取り直さない | プリスケーラ 2 のステート |
| n05 ロードでクロックの端数を戻さない | セーブとロード |
| n06 ロードで変換器のサンプルを戻さない | セーブとロード |
| n07 サンプルの間の位置を見ない | FM のレベル、FM と SSG の混ざる成分 |
| n08 チップのレートが高くても sinc を広げない | SSG の混ざる成分（12.9 dB） |
| n09 sinc の遮断を 1 オクターブ下げる | FM のレベル（−29.6 dB）、FM の混ざる成分 |

| n13 同じくプリスケーラ 2 だけ誤る（表の端） | SSG の音程（プリスケーラ 2） |
| n14 同じくプリスケーラ 3 だけ誤る | SSG の音程（プリスケーラ 3） |

n15 は最初、**SSG の混ざる成分の項目を通った。** 出力が無音だと当てはめの残りも 0 になり、
比が上限値になるため。レベルが出ていることを条件に足して塞いだ（FM 側にも同じ条件を足した）。
n12 も同じ条件で捕まるようになった（音程が 2 倍になっても、2 倍の音は当てはめる整数倍に
含まれるので、残りだけでは見分けられない）。

### 4.3 試験のときに踏んだこと

- **試験 ROM の誤り**: 最初の版はリズムと区間 5 の回数を E / DE で数え、ループの中で
  `regs`（D と E を壊すと自分で書いた）を呼んでいた。リズムが延々と繰り返され、以降の区間が
  鳴らなかった。ホスト probe で同じ手順が鳴り終わることを確かめてから録音を詳しく見て、
  0 の区間を挟んだ打音の繰り返しだと分かった。回数はメモリに置く形に直した
- **`/romtype1 NORMAL` を付けると ROM が挿さらない。** C-BIOS が「No cartridge found」を出した
  （**確認済み**、画面）。付けなければ挿さる。原因は調べていない（**未確認**）。試験は付けずに走らせる
- 最初の数回は長いパス（約 190 文字）の ROM を渡しており、そのときも無音だった。
  **パスの長さが原因かは未確認**（その実行の画面は撮っていない）。試験は `%TEMP%` の下の短いパスに置く
- 録音が全部 0 のとき、エミュレータが動いていないのか ROM が挿さっていないのかは録音からは
  分からない。本体の PSG で目印を鳴らす版と、メニューからのスクリーンショットで切り分けた

### 4.4 確かめずに残してあること

- 実機の BIOS の機種（HB-F1XDJ+ など）での試験。エミュレータの中の試験は C-BIOS だけ
- マシン構成のスロットに置いた場合（特殊カートリッジとしては挿した）
- 実機のソフト（VGMPlay MSX など）での再生
- 音量の釣り合い、レート変換の音質（人が聴いていない。§4.5 の測定は数字だけ）
- ADPCM-B の再生（probe は RAM への書き込みまで）
- 実行中にプリスケーラを切り替えた瞬間の音（変換器のサンプルを捨てるので途切れうる。音程が追従することは確かめた）
- ミキサーのレートを実行中に変えたとき（`ym2608SetSampleRate`）と、44.1 kHz 以外のレート。probe のスタブは 44.1 kHz 固定
- 公開済みの `v3.1.1-makoto.2` で実際に保存したステートを `588325e5` で読むこと（古い形のステートを**模した**版では読めた。§4.5）
- `588325e5` の Win32 のビルド（x64 しか組んでいない）
- OPNA の割り込みを許可しながら処理ルーチンを持たないソフトの挙動（実機と同じく割り込みが止まらなくなるはず）
- FM と SSG の期待値の式が YM2608 の原典と一致すること（記憶による。エミュレータとホストで一致しているが、どちらも ymfm なので独立ではない）
- `gcc/Makefile` と msvc2026 でのビルド

### 4.5 FM と SSG を実レートで回す（2026-10-04、`588325e5`）

**発端**: openMSX の upstream に、別の作者による Makoto の実装が PR として出ている
（https://github.com/openMSX/openMSX/pull/2209）。そのレビューで、ymfm の `generate()` に由来する
負荷と音質の問題が指摘された。利用者の指示で、こちらに当てはまるかを測り、対策を入れた。

議論の詳しい記録は、姉妹フォーク madscient/openMSX_Y8960 の枝 `makoto-native-rate` の
`doc/fork/makoto/implementation-plan.md` にある（2026-10-04 に `07edfbcc3` を読んだ）。
PR の本文とコメントも読んだ（同日、head `e34f671e6`、open）。**ここには流れだけを書く。**

#### 議論の流れ

PR に書かれた測定と実機の結果は**伝聞**である。こちらでは確かめていない。

| | 誰が | 内容 |
|---|---|---|
| 1 | レビュー担当（openMSX のメンテナ） | PR は ymfm を 1 MHz（`OPN_FIDELITY_MAX`）で回している。他の音源より高くつき、無音のときの最適化も無い |
| 2 | 姉妹フォーク | fidelity ごとの負荷を測って投稿した。無音で MAX は MIN の約 2.2 倍 |
| 3 | レビュー担当 | ymfm を読んだ結果、fidelity は FM と SSG を共通のレートに揃えるために**同じサンプルを繰り返しているだけ**だと分かった。繰り返し（ゼロ次ホールド）は高域を下げる。実機は FM+ADPCM を 55.6 kHz のデジタルで DAC に渡し、SSG はアナログの端子に出すので、こういう 1 MHz の信号はどこにも無い。**55.6 kHz ステレオと 250 kHz モノラルの 2 本に分ければ、速く、音も良くなる** |
| 4 | 姉妹フォーク | 試作した。`ym2608` の protected メンバーを継承クラスから回せば **ymfm を変えずにできる**。出力は `generate()` とサンプル単位で一致し、プリスケーラにも追従できる。負荷は MIN と同程度で MAX の約半分。無音のバッファをミキサーに知らせると、無音のとき約 3 割減る |
| 5 | PR の作者 | 同じ方式を PR に取り込んだ。その過程で、**ロードの後に `generate()` 用の設定が復元されない**不具合を見つけた（プリスケーラ 2・3 で、作り直したコアが食い違う） |
| 6 | レビュー担当 | 8 MHz ではデータシート上プリスケーラ 6 だけが規格内。SSG の 2/3 倍は ymfm が 1 本に混ぜるときの係数で、実機には無いと思う |
| 7 | 両者 | `ym2608` クラスを写して openMSX 側に持つ形にした。SSG を openMSX の `AY8910` に置き換える案、FM と ADPCM の本当の無音検出、`save_restore` の置き換えは検討中 |

#### こちらに当てはまるか

修正前の `b2d4d185` を測った（**確認済み**: `opna-probe.exe` の判定と `--survey`。Win10 機）。

- **負荷**: 当てはまり方が違う。こちらは最初から `OPN_FIDELITY_MIN`（clock / 48）を選んでいたので、
  PR で問題になった 1 MHz の生成は**もともと無い。** 姉妹フォークの測定でも、実レートは MIN と同程度だった
- **音**: 当てはまる。**ymfm の繰り返しに、こちらのグルーの平均が重なっていた。** `generate()` は
  FM の 1 サンプルを 3 回繰り返し（MIN、プリスケーラ 6）、グルーはそれを**整数個**（3 個か 4 個）ずつ
  平均してミキサーの 1 サンプルにしていた。平均の区切りは 6 µs 刻みでしか動かないので、ミキサーの
  サンプルごとに区切りの位置と長さが揺れる。高い音ほどレベルが下がり、元の音に無い成分が混ざる
- **セーブステート**: 当てはまる。プリスケーラ 2 で保存して作り直したチップに読むと、FM が 1/3 の
  音程になった（261.94 Hz、期待 785.83 Hz）。ymfm の状態はプリスケーラを戻すが、`generate()` が
  そこから決める繰り返しの回数は戻さない

**「残り」の測り方**: 音の基本周波数の整数倍と直流を、ナイキスト周波数の手前まで最小二乗で
当てはめ、当てはまった電力と残った電力の比を dB で出す。**音の周期がチップのサンプルの整数個に
なるように選んである**ので、チップ自身の歪みは整数倍に乗り、残るのは変換が足した成分になる。

**SSG の低い音で残りが 40 dB 台に留まるのは、ナイキスト周波数のすぐ上の倍音が折り返す分である。**
矩形波の倍音は 1/n でしか下がらず、sinc の遮断は 22 kHz の前後数 kHz に幅を持つ。
根拠は、sinc を長くする（遮断の幅を狭める）と減ること（**確認済み**: 880 Hz の残りは片側 8 / 12 / 16 で

見てはいない）。

（**確認済み**: プリスケーラ 6 / 3 / 2 で不一致 0。書き込みを 3 つ抜くと両方が食い違う）。この試験は
姉妹フォークの `doc/fork/makoto/tests/native-rate-check.cc`（`07edfbcc3`）を写して probe に組み込み、
プリスケーラ 3 の組を足したもの。ymfm は両方のリポジトリでバイト単位で同じである
（**確認済み**: 9 本の blob のハッシュが一致）。

#### 作り

| | どうしたか | 前提・補足 |
|---|---|---|
| 生成 | `Ym2608Chip`（`ymfm::ym2608` を継承）から `clock_fm_and_adpcm()`・`m_last_fm`・`m_ssg` を直接回す。**ymfm は変えていない** | これらが protected のままである限り成立する。private になればビルドが `YM2608.cpp` で止まる（黙っては通らない）。そのときは ymfm に小さな公開関数を足すことになり、「無改変」（§2）を変える判断が要る。`ymfm/README.md` にも書いた |
| プリスケーラ | 書き込みのたびにチップのプリスケーラを見て、変わっていたら両方のレートを取り直す | 取り直すと変換器が持っているサンプルを捨てる。PR のレビューによれば、8 MHz でプリスケーラを変えるのは規格外で、そういうソフトはまず無い |
| 変換 | ストリームごとに窓付き sinc（Blackman、片側 12 個のゼロ交差を、低い方のレートで数える）。ミキサーのサンプルがチップのサンプルの間のどこに落ちるかは、クロックの端数（整数）から求め、ミキサーの 1 サンプルを 1024 に割った刻みで係数の行を選ぶ | 係数は 14bit。**行ごとに和をちょうど 1 にしてある**（一定のレベルが、位置によらず一定に出る）。表の大きさはレートによらず 1 本あたり約 25,000 係数。44.1 kHz では FM が 32 タップ × 813 行、SSG が 138 タップ × 181 行 |
| 無音 | 変換器に入った値がタップ数ぶん続けて 0 なら、積和を省いて 0 を返す | **チップは止めない。** 止めると ADPCM-B のステータスが進まなくなる |
| 混合 | 変えていない（§4.1） | 修正前と同じ釣り合いで鳴る |
| セーブステート | `resampleAcc` をやめ、`mixerRate`・`fmAcc`・`ssgAcc`・`fmHistorySize`・`fmHistory`・`ssgHistorySize`・`ssgHistory` を足した。ミキサーのレートと大きさが一致するときだけ戻す | 下の「外に出る値」 |

16bit のサンプル × 係数の絶対値の和が 32bit に収まること（和の最大は 35,756、限度は 65,536）と、
表の大きさは、同じ式を Python で計算して見た（**確認済み**: ミキサーのレート 11,025 / 44,100 /
48,000 / 96,000 Hz、プリスケーラ 6 と 2 の 9 通り）。

**古い形のステートも読める**（**確認済み**: 足した 7 項目を書かずに保存する版を作って probe に掛けた。
ロードの後の音程は合い、落ちるのは「サンプル単位で同じ」の 1 項目だけ。ストリームが頭から始まるため）。

#### 負荷

`opna-probe.exe --bench`。ymfm とグルーだけを回し、1 秒ぶんの音を作るのに掛かるホストの時間を測る
（30 秒ぶんを 3 回回した最短）。それを版を替えながら 7 巡して、最小と中央を取った（**確認済み**、Win10 機）。
「演奏中」は FM 6 声（アルゴリズム 7、TL 0）と SSG 3 声（音量 15）を鳴らしたまま。鳴っていることは
出力のピークで見た。

| | 無音（最小 / 中央） | 演奏中（最小 / 中央） |
|---|---|---|
| 修正前 `b2d4d185` | 16.75 / 17.03 ms | 29.75 / 31.73 ms |
| sinc 片側 8 | 14.99 / 15.34 | 29.57 / 30.42 |
| **sinc 片側 12（採用）** | 14.97 / 15.51 | 29.88 / 31.06 |
| sinc 片側 16 | 15.18 / 15.68 | 30.66 / 32.44 |

- **無音は約 1 割減った。** 7 巡の範囲は修正前が 16.75〜18.05、採用版が 14.97〜16.07 で、ほぼ重ならない
- **演奏中は差が出ていない。** 1 つの版の中のばらつき（修正前で 29.75〜32.52）の方が、版の間の差より大きい
- 1 コアに対する割合にすると、無音で約 1.5%、演奏中で約 3%。**エミュレータ全体の中での割合は測っていない**
- 残っている負荷は ymfm が FM と SSG を回す分で、無音でも止められない（上の「無音」）

#### 姉妹フォークと違えたところ

| | openMSX_Y8960（`makoto-native-rate`） | こちら | 理由 |
|---|---|---|---|
| 変換 | 本体のリサンプラに任せる | グルーの中で sinc | blueMSX のミキサーは変換をしない。チャンネルのコールバックは、ミキサーのレートのサンプルを返す決まり（**確認済み(読解)**: `AudioMixer.c` の `mixerSync`） |
| デバイスの数 | FM と SSG で 2 つ（レートが違うので分けるしかない） | ミキサーのチャンネルは 1 つのまま | 変換をグルーが持つので、分ける必要が無い。分けるなら種別の新設（§3.1 で見送り）か、SSG を本体の PSG のスライダーに入れることになる |
| 無音 | バッファを `nullptr` で返して、本体にリサンプルを省かせる | 変換器が積和を省く | 省ける仕事の在りかが違う。こちらのミキサーも `NULL` を返せばそのチャンネルを飛ばすが、省けるのは掛け算 2 回 |
| SSG の 2/3 | デバイスの増幅率にまとめた | サンプルごとに掛ける（`generate()` と同じ式） | チャンネルが 1 つなので、FM との比はグルーの中で決めるしかない。SSG の 3 声の和を 16bit に収める役目もある |

#### 外に出る値

セーブステートの節 `ym2608` の中の項目名を足した（上の「作り」）。**`588325e5` はまだ公開していない**ので、
公開までは文字列 7 個を変えるだけで済む。公開した後に変えると、前の名前で読む分岐が要る。
**利用者には事後の報告になった**（2026-10-04）。

#### 見送ったもの

- **sinc を片側 16 にする** — 見送り。20.8 kHz のレベルが −2.25 → −1.54 dB、SSG 880 Hz の残りが
  45.5 → 50.5 dB に良くなるが、演奏中の負荷が修正前を上回る測定値になった（中央で +2%。ばらつきの中）。
  **負荷を修正前より増やさない**ことを基準に 12 にした。変える値段は定数 1 個（`SINC_ZERO_CROSSINGS`）
- **片側 8 にする** — 見送り。SSG 2,976 Hz の残りが 68.8 → 51.4 dB に落ち、17.4 kHz で −0.16 dB、
  20.8 kHz で −3.16 dB になる。負荷の差はばらつきの中
- **上流が OPLL に使っている `OPLL_RateConv`（Emu2413 の 16 タップ sinc。`NukedOpllBackend` が借りている）を
  借りる** — 見送り。250 kHz の SSG には短い（sinc を広げないと SSG の残りが 12.9 dB になる。n08）。
  FM だけに使うと、位置を倍精度の端数で数える変換器と、整数でクロックを数えるこちらの間でずれうる
  （**推測**: `emu2413.c` を読んだだけで、ずれを出してはいない）
- **SSG を別のミキサーチャンネルにする** — 見送り。上の表のとおり
- **ymfm の ADPCM-B の転送を、実機の報告に合わせて直す** — 見送り。ymfm を無改変で持つ決定（§2）を
  変えることになるので、**利用者の判断が要る。** 中身は下の「ymfm の挙動」
- **`ym2608` クラスを写して自前で持つ**（PR の最終形） — 見送り。同じ理由
- **SSG を本体の `AY8910.c` に置き換える**（PR で検討中の案に当たるもの） — 見送り。調べていない

#### ymfm の挙動で、実機と違うという報告がある点

PR の作者が Makoto の実機で確かめて ymfm を直した点（**伝聞**）。**こちらの ymfm は直していない。**
ADPCM-B の RAM の端を使うソフトが動かなかったら、まずここを見る。

| | こちらの ymfm | 実機の報告（伝聞） |
|---|---|---|
| ADPCM-B の CPU からの書き込み。開始も終了も `0000h`（1bit DRAM）で `A1 A2 A3 A4` を書く | RAM は `A1 A2 A3 FF`。**最後の 1 バイトが書かれない** | 4 バイトとも書かれる |
| ADPCM-B の CPU からの読み出し。RAM に `B1`〜`B8`、limit `0000h` | `B1 B2 B3 B1 B2 B3 B1 B2`。**limit の最後の 1 バイトを読む前に 0 番地へ戻る** | `B1 B2 B3 B4` を繰り返す |
| 終了アドレスまで書かずにモードを切り替えたあとの読み出し | **未確認**（ymfm にはこの挙動が無い、と PR にある） | ADPCM のリセットまで、最後に書いたバイトが返る |

左の列の上 2 行は、使い捨てのプログラムを probe のスタブと組んで走らせて見た（**確認済み** 2026-10-04。
姉妹フォークが同じ版の ymfm で見た結果と同じ）。

ほかに、姉妹フォークが ymfm の挙動として記録している点が 2 つある（どちらも**実機との突き合わせは
されていない**。こちらでは走らせていない）: フラグマスク `110h` のリセット値が `1Ch` で、書き換えるまで
BRDY がステータス 1 に出ないこと。ADPCM-B の EOS と BRDY が、ステータス 1 を読んだときにしか
IRQ に反映されないこと。
