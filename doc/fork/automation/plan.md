# キー入力の注入と、ウィンドウを出さない実行 — 計画

対象読者は開発者と AI。Y8960 とは独立した、エミュレータを外から操作するための機能。

**動機**: 起動を伴う試験（`doc/fork/y8960/implementation-plan.md` §9.8）では、
キー入力を送れず、試験のたびにウィンドウが出る。とくにファームウェア
（`y8960bas.rom`）は BASIC の拡張命令を打たないと試せない。

## 1. 決まったこと（2026-09-13 ユーザー判断）

| | 決定 | 前提 |
|---|---|---|
| キー入力の受け口 | **`WM_COPYDATA` だけ**。起動オプション（`/type`）は当面作らない | 打つ時刻を送る側が画面を見て決める使い方が主であること |
| ウィンドウを出さない実行 | **同時に作る**。今の Win32 版のウィンドウを隠す形（案 A） | デスクトップのある環境で走らせること。無い環境（サービスとしての CI）が要るなら専用の実行ファイル（案 B）を別に考える |
| 上流との関係 | **上流（blueMSX+）へのプルリクエスト候補として作る** | Y8960 に依存しない汎用機能であること |

上流候補なので、**`upstream/develop` から切った枝に、コードだけのコミットで作る**
（`doc/fork/README.md` の「上流へ出すとき」）。フォークへはマージで取り込む。
この文書は上流に出さない。

### 見送ったもの

- **起動オプションで打つ（`/type`）** — 当面見送り。起動時に 1 回だけ、事前に決めた
  時刻でしか打てず、結果を見て次を打てない。無人の 1 回きりの試験には向くので、
  必要になったら打鍵器を共有して足せる（40〜80 行の見込み）
- **専用のヘッドレス実行ファイル（案 B）** — 見送り。プラットフォーム層 181 関数の
  実装が要り、上流がソースを足すたびにプロジェクトの追従が要る
  （保守されていない SDL 版がその状態）

## 2. 調べて分かったこと（**確認済み(読解)**）

| | |
|---|---|
| キーマトリクス | `MsxPPI.c` が `inputEventGetState(EC_*)` で組む。外から `inputEventSet` / `inputEventUnset` を呼べば押したことになる（`Actions.c` の `actionKeyPress` が既にある） |
| キーバインド定義 | **ホストのキー（DirectInput）→ `EC_*` の変換だけに効く**（`Win32keyboard.c` の `bindingsDikForEc`）。`inputEventSet` は `eventMap[]` に直接書くマクロ（`InputEvent.h`）なので、**そこへ注入すればバインドを通らない**。`EC_*` → キーマトリクスの対応は `MsxPPI.c` に固定で、設定では変わらない。**逆に、ホストのキーイベントを合成する作り方（`SendInput` や `WM_KEYDOWN`）ではバインドとフォーカスの影響を受ける**ので採らない |
| ホストのキーボード | **フォーカスが無いと、ポーリングのたびに全キーを消す**（`keyboardUpdate` → `keyboardResetKbd` → `inputEventReset`。エミュレータのスレッドが同期ごとに呼ぶ）。**「フォーカス」は `GetFocus()` で判定しており、スレッド単位なので、別のプログラムが前面にあっても真になりうる。** キーボードの DirectInput は `DISCL_BACKGROUND` で開くので、そのとき前面のプログラムで打ったキーまで読む（§4 の追記。**確認済み**） |
| 既存の `WM_COPYDATA` | ファイル起動の受け渡しに使っている（`Win32.c`、識別子 `LAUNCH_COPYDATA_ID` = `0x424D5846`）。識別子で区別して足せる |
| 2 つ目の起動の転送 | 引数が登録済み拡張子のファイル 1 個のときだけ。オプション付きの起動は常に新しいインスタンス |
| キー名 | `InputEvent.c` に既存の名前がある（`f1` `stop` `return` `graph` `code` …）。キーボード設定ファイルと同じ名前 |
| スクリーンショット | フレームバッファから CPU で描く（`createScreenShotEx`）。ウィンドウに依存しない |
| `/mute` | 全体音量を 0 にするので **WAV にも無音が書かれる**（`AudioMixer.c` の音量計算） |
| ダイアログ | `Win32.c` だけで `MessageBox` が 22 か所 |

**以下の配列の調べは、文字列を送る当初案のためのもの。** キーマトリクスを送る方式（§3）では
エミュレータは使わないが、送る側の道具が配列を選ぶときの手がかりとして残す。

**キー配列は本体 ROM の `002Bh` で分けられる見込み**（**確認済み**、5 本の ROM で）:

| ROM | `002Bh` | `002Ch` |
|---|---|---|
| Sony HB-F1XDJ | `00` | `00` |
| C-BIOS JP | `00` | `00` |
| C-BIOS（US） | `21` | `02` |
| C-BIOS EU | `A1` | `02` |
| C-BIOS BR | `21` | `02` |

`002Bh` の下位 4bit が 0 なら日本配列、それ以外を国際配列とみなす。
**5 本以外で成り立つかは未確認**（とくに `002Ch` の値の意味は確かめていない）。

## 3. 外に出る値

### 決まったもの（2026-09-13 ユーザー判断）

| # | 値 | 決定 |
|---|---|---|
| 1 | キー入力の `WM_COPYDATA` 識別子 | `0x424D5854`（`BMXT`。既存の `BMXF` に並べる） |
| 4 | 打ち終わりを知る手段 | 同じ識別子で空の要求を送ると、残りの件数を返す（0 で打ち終わり） |
| 6 | 隠す起動オプション | `/hidden`。ウィンドウを表示せず、スピーカーへは出さず、WAV の書き出しは生かす |
| 7 | 隠したときのダイアログ | 起動失敗は出さずに終了コードで返す。保存先を尋ねるダイアログは出さず自動の名前にする。それ以外は今回塞がない |
| 8 | 終了 | 新しい口は作らない。送る側が `WM_CLOSE` を送る |

### 方針が変わったもの — 文字列ではなくキーマトリクスを送る（2026-09-13 ユーザー提案）

**エミュレータは文字を解釈しない。** 送る側がキーマトリクスの行とビットを押し・離し、
どの文字になるかは MSX 側（BIOS）が自分の配列で決める。

これで当初の案 2（文字の符号化）・3（改行と特殊キー）・5（配列の自動判定）は要らなくなる。
文字列を打ちたいときの「文字 → キーマトリクス」の変換は送る側の道具が持つ。

**openMSX にも同じ粒度のコマンドがある**（**確認済み(読解)**: openMSX_Y8960 の
`src/input/Keyboard.cc`、`keymatrixdown <row> <bitmask>` / `keymatrixup <row> <bitmask>`）。

| # | 値 | 決定（2026-09-13 ユーザー判断） |
|---|---|---|
| 2' | 要求の形式 | ASCII のテキスト、NUL 終端。空白区切りのコマンド列 |
| 3' | コマンド | `d <row> <mask>` 押す、`u <row> <mask>` 離す（openMSX と同じ引数）、`w <ms>` エミュレーション時間で待つ。数値は 10 進か `0x` 付き 16 進 |
| 5' | 対象の機種 | MSX 系の基盤だけ。行 0-11（`MsxPPI.c` の行列）。それ以外の基盤や範囲外の値を含む要求は丸ごと拒否 |
| 9 | 残りの件数（#4）の数え方 | 未実行のコマンドの数（`w` も 1 件） |

### 隠したインスタンスと人の操作の干渉（**確認済み(読解)**、2026-09-13）

| 経路 | 干渉するか | 根拠 |
|---|---|---|
| キーボード | **していた（人 → 試験）。直した** | 当初は「フォーカスがあるときだけ読むので干渉しない」と書いたが誤り。`/hidden` でも `hasFocus` がほぼ常に真だった（**確認済み**、一時的な記録で 30 回中 29 回）。§4 の追記を見よ |
| ゲームパッド | **する（人 → 試験）**。フォーカスが無くてもエミュレートしたジョイスティックに届く | `joystickUpdate` にフォーカスの判定が無く、`Win32.c` に「Pads keep feeding the emulated joystick unfocused」とある |
| マウス | しない。MSX マウスはロック中だけ動く | `mouseEmuHandleRawInput` が `hasMouseLock` を見る。非表示ならロックできない |
| ファイルのダブルクリック | **する（双方向）**。2 つ目の起動が隠したインスタンスへ ROM を渡し、`SC_RESTORE` と `SetForegroundWindow` を送る | `findRunningInstance` は `FindWindowEx` で探す。`FindWindowEx` が非表示のウィンドウも見つけることは API の仕様の知識で、**未検証** |
| 設定ファイル | **しうる**。終了時に `bluemsx.ini` を書く | `propDestroy` → `propSave`。人が使っているインスタンスと同じ場所なら後から終わった方が勝つ。既存の `/rootdir` / `/inifile` で分けられる |
| 出力フォルダ | しうる。`Screenshots` / `Audio Capture` を共有する | 同上。`/rootdir` で分けられる |
| 音 | しない（`/hidden` でスピーカーへ出さない、#6） | — |

|---|---|
| 10 | 隠したインスタンスは、ダブルクリックの転送先にならない（転送を受け付けない） |

## 4. 実装（2026-09-13）

**上流候補の枝 `feature/key-matrix-input`**（`upstream/develop` の `90e2920b` から）に
コードだけの 1 コミット `fe8d73d4`。`feature/y8960` へは `70db3c17` でマージした（衝突なし）。
**上流へは PR #81 として提案した**（2026-09-13）。

| ファイル | 内容 |
|---|---|
| `Src/Input/KeyMatrixInput.{c,h}`（新規） | 要求の解析、キュー、ボードタイマでの実行。行・ビット → `EC_*` の表は `MsxPPI.c` と同じ並び |
| `Src/Board/Board.c` | `boardRun` の前後で `keyMatrixInputBoardStart` / `Stop` |
| `Src/Win32/Win32.c` | `WM_COPYDATA` の受け口、`/hidden` の振る舞い一式 |
| `Src/Win32/Win32keyboard.{c,h}` | `joystickSetPolling` |
| `Src/Emulator/CommandLine.c` | オプション表に `hidden` |
| ビルド定義 3 系統 | 新規ファイルの登録 |

**`/hidden` でビデオドライバに描かせないと、画面の写しが真っ黒になった。**
ドライバが描くときにビューフレームを切り替えているため（`frameBufferFlipViewFrame`）。
隠したときは描かずに切り替えだけ行う。

**実行が終わるとキューを捨て、押していたキーを離す。** 次の実行に持ち越さない。

### 追記: 隠したインスタンスがホストのキーボードを読んでいた（2026-09-13）

**見つけた経緯**: ファームウェアの試験で、打った行がときどき大きく化けた（`SCREEN,,0` が
`SCREPEN,,0` になり、以降の行がほぼ全滅）。同じ行を条件を変えて打つと化けず、再現しなかった。

**原因（**確認済み**）**: 2 つが重なっていた。

| | 内容 | 確かめ方 |
|---|---|---|
| 1 | `/hidden` のインスタンスが「フォーカスあり」と判定され、DirectInput がバックグラウンドでホストのキーボードを読んでいた | `keyboardUpdate` に一時的な記録を入れ、`/hidden` で `hasFocus` が 30 回中 29 回真、修正後は 30 回中 0 回 |
| 2 | フォーカスが無いとキーボード層がポーリングのたびに `eventMap` を消すので、注入したキーは数ミリ秒で離される | 1 を直し 2 を直さないビルドで、1.5 秒押し続けたキーが 1 文字も出なかった。両方直したビルドではオートリピートで 26 文字出た |

化けた回に実際にホストのキーが打たれていたかは確かめていない（**推測** — 化け方が
非決定的で、条件をそろえると再現しないことからの見立て）。

**修正**（PR #81 に追加したコミット `189b5deb`）:
`/hidden` のときはキーボードのフォーカスを与えない。注入したキーは `eventInjected[]` という
別の表に持ち、`inputEventGetState` が `eventMap` と OR して読む。`inputEventReset` は
`eventMap` だけを消す。PR #81 には経緯をコメントで書いた。

**押す長さ**: §5 で「40 ms では取りこぼす。BIOS の走査間隔による」と推測したが、
その回もこの不具合の影響下にあった。修正前の実行ファイルでも、MSX2 の BIOS で 40〜300 ms の
いずれでも 1 行が正しく入った回がある（**確認済み**）ので、取りこぼしの原因は切り分けられていない。
注入を別の表にした後の実行ファイルでも、C-BIOS で 20 ms は文字が落ちた（**確認済み**）。道具の既定は 80 ms のまま。

### 追記: `w 0` でキューが止まっていた（2026-09-16、PR #81 のレビューで指摘）

**原因（**確認済み(読解)**）**: `onTimer` は待ちの終わりを `time + 待ち` で決める。
`time` はタイマ自身の時刻で（`boardTimerCheckTimeout` が `timer->timeout` を渡す）、
呼ばれた時点の時計はそれ以上に進んでいる。`w 0` だと過去の時刻で登録し直すことになり、
`boardTimerAdd` は期限切れとしてタイマをリストに戻さない（`Board.c` の
`// Time has already expired`）。以降のコマンドは実行されない。
比較は `<` なので時刻がちょうど同じなら外れないが、実測では止まった（下表）。

**修正**（PR #81 に追加したコミット `fdaa148a`）: 登録し直す時刻が現在時刻以下なら
現在時刻 + 1 にする。**0 を `parse` で拒否しない**のはレビューの希望による
（待ち時間を計算するスクリプトが 0 を出しうる）。

| 確かめたこと（`/hidden`、C-BIOS、`keytest.rom`） | 修正前 | 修正後 |
|---|---|---|
| 待ちの無いところに `w 0` を 1 つ → 残り件数 | 1 のまま | 0 |
| `w 10 w 0 w 0` の後に、各キーの前に `w 0` を挟んで `HELLO, MSX 123!` | `w 10` だけ済んで 109 件中 108 件が残り、画面に何も出ない | 残り 0、画面に `KEYS: OK` |

いずれも**確認済み**（修正前後の実行ファイルで同じ試験を流し、画面の写しも見た）。
2 行目は 1 行目と別のプロセスで流した（1 行目で止まったタイマを引き継がないように）。
**`run-keytest.ps1` に 2 項目足した**（`w 0 from idle drains`、`w 0 after a wait drains`）。
修正を外した版では 2 項目と `queue drains` の 3 つが NG、修正後は 12 項目すべて OK
（**確認済み**）。2 つ目は 1 つ目で止まったタイマを引き継ぐので、単独での判別力は上表の 2 行目で示した。

**`+ 1` と「現在時刻そのもの」の違いは、この試験では見分けられない。** 時刻がちょうど
同じならタイマは外れないので、どちらでも通るはず（**推測** — `boardTimerAdd` の比較が
`<` であることからの見立て。壊した版で確かめていない）。`+ 1` は余裕として置いた。

**`KeyMatrixInput.c` の `matrix[][]` は触らない**（レビューの依頼）。`MsxPPI.c` の
`ROW0`〜`ROW11` と同じ内容を別の形で持っているが、上流がマージ後に `MsxPPI` 側の表から
引く形に整理する予定。**フォーク側で先に直すと、上流の整理と衝突する。**

`tests/keytest.asm`（C-BIOS 上で `CHGET` の結果を表示し、期待する行と比べる）と
`tests/run-keytest.ps1`。

| 不正な要求 5 種（行 12、キーの無いビット、未知のコマンド、数値の欠落、符号）を拒否 | **確認済み** |
| 残り件数が打ち終わりで 0 になる | **確認済み** |

| `/hidden` で表示されているウィンドウが 0 個 | **確認済み**（`EnumWindows`） |
| `/hidden` で、渡されたファイルを受け付けない（`0`） | **確認済み**。表示ありでは `1` |
| `/hidden` で WAV が録れる（音のドライバを開かない状態で） | **確認済み**（`sndtest` が PASS） |
| `/hidden` でコマンドラインの誤りがダイアログを出さず stderr と終了コード 1 | **確認済み**（存在しない機種、ROM の無い機種） |

**押す長さは 80 ms にした。** 40 ms では `HELLO, MSX 123!` が `HELL, MS 123` になった
（**確認済み**）。当時は BIOS の走査間隔によると推測したが、その回は §4 の追記の不具合の
影響下にあったので、原因は切り分けられていない。

**起動待ちはエミュレーション時間で行う。** 実時間 8 秒待ってから打った回で、
打ち終わった後に ROM が読み始め、1 文字も入らなかった（**確認済み**）。
`w 8000` を最初に積めば、ホストの速さによらない。

## 6. 確かめていないこと

- **起動失敗で終了コード 2**。コマンドラインの検査が先に捕まえるので、この経路に
  届かなかった。設定ファイルの機種に ROM が無い場合は、別の機種で起動してしまった
- **ゲームパッドを読まないこと**。パッドが無い
- **スピーカーから音が出ないこと**。コードは音のドライバを開かない（**確認済み(読解)**）が、聴いていない
- **表示ありでのフォーカスとの干渉**（人がウィンドウを触るとキーがリセットされる）
- **BASIC の実行中にキーバッファが溢れないか**
